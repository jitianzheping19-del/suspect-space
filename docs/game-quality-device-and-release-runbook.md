# 実機確認と公開復旧

これは実行手順と記録用紙。記入されていない項目は未実施であり、合格ではない。

## 実機での最終確認

人間5人以上で実施する。PC・iPhone・Androidを含め、可能ならiPadも追加する。OS、ブラウザ、端末型番、サイトの版、通信方式、画面方向、人数、マップ、役職設定を記録する。初見ユーザーには事前に操作を説明せず、困った時点と試した操作を記録する。

| 時間の目安 | 操作 | 観察する結果 |
| --- | --- | --- |
| 0〜5分 | 旧アカウントでログイン、ロビー参加、衣装・残高確認。マイクとスピーカーミュートを各々切替 | 未入力エラーなし、既存の所持品維持、選択表示と実音声の一致 |
| 5〜15分 | 開始→移動しながら視点/能力→タスク→会議→全員投票→勝敗→ロビー | 誰の端末も進行停止しない、タスク/投票/勝敗一致、二重実行なし |
| 15〜25分 | 別の役職で繰返す。1人がバックグラウンド、回線切替。ホストの回線を切断して復帰/交代 | 役職・生死・所持品が一致、交代待機が分かる、本人が選んだミュートを維持、古い画面なし |
| 25〜30分以上 | さらに1試合。サッカーへの出入り、読み込みの再試行、画質の往復切替 | 連続3試合終了、スマホの操作/カメラ/音声復帰、極端なフレーム低下なし |

この時間は目安。3試合が30分で終わらなければ延長する。待機だけで30分を満たしたことにしない。通話は全組合せについて双方から短い同じ文を読み、聞き手が内容を復唱する。エコー・途切れ・距離減衰・ミュート時の無音を記録する。実際の参加者への連絡はこの作業では行っていない。

### 発熱・電池の比較条件

### 対戦・公平さの記録

1試合ごとに、版・人数・マップ・役職/陣営・能力設定・勝者・時間・切断・問題を記録する。全役職の同時勝利ケースは「先に成立を確定する条件」「追加勝利できる役職」「切断者の扱い」を表にして仕様と照合する。少数試合の勝率だけで大幅な能力変更を決めない。

UIの色やボタンの統一、説明の分かりやすさは、自動の矩形チェックでは完了にしない。縦/横、ブラウザの文字拡大、ノッチ、キーボード表示を含めて確認する。

## 公開前

1. 最新ソースとの差分を統合した隔離コピーで `node tools/check-quality-release.mjs` を実行する。最後の変更後の結果を保存する。
2. 対象変更の追加テストと上記の実機確認を終える。失敗/未実施の項目を公開判断から隠さない。
3. 公開するコミット、成果物全体、SHA-256一覧、テスト結果を同じリリース記録に保管する。HTMLだけでなく、ハッシュ付きJS/CSS・Service Worker・画像等も保管する。
4. **直前に成功したGitHub Pagesのデプロイ**のコミットと成果物を確認して保管する。この作業の開始SHA `2d415f9…` は、直前の公開版であることを確認していない。
5. 公開後に、実際のURLでログイン、参加、タスク、会議/投票、通話、再接続、旧残高を確認する。新規アクセスと既存キャッシュの両方で確認する。

一括確認ツールはビルド・ローカル検証だけを行い、公開しない。今回のローカル変更ではGitHub Actionsにもこの確認を追加した。チェックが失敗すると公開へ進まない。確認後の全配信物とSHA-256一覧を `verified-game-release` として90日保管する。GitHubでの初回実行は未実施。

## 端末での記録機能

新版で「設定→画質→動作確認の記録」を開き、端末・版・画質などをメモして「記録を開始」。実プレイを30分以上行い、「記録を終了」→「記録を保存」でJSONを保存する。名前やPINはメモに書かない。バッテリーAPI非対応端末では残量を手動でメモする。温度と音声品質はこの機能では測れない。通信値は位置等のRTCペイロードだけで、音声や配信の総通信量ではない。リロード時は記録を終了し、保存済みの記録を取り出せる。

## 検証済み配信物の復元workflow

GitHub Actionsの「Restore a verified Space Suspect release」で、復元したい成功済み `pages.yml` のrun IDを指定する。同じリポジトリのmain・成功runであること、配信物全ファイルのSHA-256が一致することを確認して配信する。保存期限内の新しい形式の成果物が必要で、この変更以前のrunには保存物がない。以前の成功配信物は別途確保する。アカウントや所持品のDBは復元対象に含まない。

## 問題があった場合の切戻し

1. 影響と再現手順、問題の公開コミットを記録する。
2. 保管済みの「直前に成功したPages配信物」を、同じサイトの配信物として再公開する。利用可能な復旧手段がソースだけなら、直前の成功コミットを隔離コピーでビルド・検証し、通常のレビュー可能な復旧コミットで公開する。履歴の強制上書きは必要ない。
3. アカウント・残高・受取記録を古い状態へ書き戻さない。この改善にはDBスキーマの移行や報酬配布識別子の変更は含めていない。
4. 配信が終わったら、HTMLとJS/CSSの版が一致すること、旧キャッシュからも再読込で復帰できることを確認する。
5. ログイン、既存所持品、1試合、通話/再接続を再確認し、復旧した時刻を記録する。
