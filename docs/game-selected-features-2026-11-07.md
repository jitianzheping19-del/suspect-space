## 保存と練習の範囲

- フレンド登録、NEWの既読、初回案内は端末内でアカウント別に保存する。別端末との同期は今回の実装範囲に含まない。
- 疑い印と証言メモはそのタブ内で、アカウント・部屋・試合ごとに保存する。チャットへ自動投稿しない。
- 写真ポーズ、撮影情報、離席状態はロビーのホスト処理で共有する。実回線の複数端末での最終確認は下記の手順で行う。
- 役職練習は実際のゲーム処理を専用iframeとメモリ内DBで実行する。実アカウントの認証・DB・音声接続、報酬付与は行わない。部屋設定や再接続先も上書きしない。
- タスク練習は練習用の完了処理を使い、本編のタスク数や所持品を増やさない。

## 自動確認

最終結果と各チェックのログは同梱の `release-checks.json` と `checks/` を参照。以下を実行する。

```sh
npm run check:quality
node tools/run-quality-browser.cjs check-all-roles.cjs
node tools/run-quality-browser.cjs check-meeting-render-recovery.cjs
git diff --check
```

一括確認はビルドを含む30段階。今回追加した検証は、状態の60秒解除、実際のキャラクターの撮影ポーズ・フレーム、部屋単位の復電、実抽選18万回と表示割合の一致、練習DBの分離、スマホ縦横・タブレット相当のUIとタッチ、タスク練習の実操作完了、10連結果の拡大・NEW・受取済み履歴、完成品での役職練習と外部接続の遮断を対象にする。

ブラウザの画面サイズを変えた確認は実機テストの代わりではない。全役職のルール検証と、代表役職の実ブラウザ練習を区別する。足音・演出・カーブの遊びやすさは人が実際に操作して確認する必要がある。

最終の一括確認は30段階すべて成功。別途、80役職・197項目の実際のホスト処理、完成品での医師・エンジニア・会議シェリフ・守護天使・てるてるの練習、3D会議の定型証言・引用・返信・説明固定とGPU復旧→2D代替→次の会議を確認した。役職練習から認証・実DB・音声・WebSocket接続が発生しないことも確認した。

3D会議の追加チェックでは、最初の試行で模擬回線が切断状態となり、入力制限により失敗した。会議の導入時刻と模擬接続を修正し、最終試行では操作と描画復旧を完走した。これは本番の通信制限を解除する変更ではない。
