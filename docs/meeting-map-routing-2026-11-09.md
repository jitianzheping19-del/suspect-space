# 会議マップの操作と部屋単位の経路

作業場所: `/workspace/meeting-map-routing-2026-11-09`。元: `5c68401`。未デプロイ。

## 原因と変更

- `resetRoundUI()` の `show('meetingMapTools',false)` が設定した `inert` と非表示の意図が、従来の会議同期では解除されなかった。見える枠の中の両ボタンがタップ不能になった。表示用の共通処理と同期し、次の会議で表示・操作状態を復帰する。別のダイアログを開いている間の背景無効化は維持する。
- 経路は部屋中心間の直線だったため、壁や屋外を横切った。往復の線を繰り返し外へずらす処理もあった。
- `meeting-location-navigation.js` で実マップの部屋・通路・穴・壁に基づく経路を計算。壁の近傍検索と経路をキャッシュする。接続できない場所へ直線で代替しない。
- ドラッグ中の通路座標は記録せず、通った部屋を順に選択する。部屋内の穴の上にあるラベルも、床内の代表位置へ対応させる。
- 線の往復オフセットに上限を設け、安全な床内に収まる範囲へ縮める。描画も床の形でクリップし、部屋ごとに順番をまとめる。つながらない選択には修正方法を表示する。
- ホストも、マップ外の座標・接続できない経路を拒否する。証言の送信・ゴーストの分離・会議単位の保存は既存方式を使う。

## 確認

- 修正前: 試合開始と同じボタン枠の非表示処理を通すと、`meeting controls must recover from round reset` で失敗。
- 修正後: `SABOTAGE_QA_BUILD=1 node tools/check-meeting-location-touch.cjs`。2D/3D会議、スマホ縦横・タブレット相当で本物のタッチ入力によるマップ・現在地の開閉を確認。
- `node tools/check-meeting-route-navigation.mjs`: 屋外を避ける通路、20回までの往復、穴・壁・代表点、切断された部屋への報告拒否。
- `node tools/check-meeting-route-input.cjs`: 中心に穴がある部屋ラベルもタップで選択し、A→B→Aを送信できること。
- 実際の3マップの52部屋に対して起点からの接続を確認し、往復を含む計3,929線分がすべて床内・壁非交差であることを検証。
- `SABOTAGE_QA_BUILD=1 node tools/check-meeting-location-reports.cjs`: ビルド済み画面と模擬DBによるホスト処理、送受信・保持・屋外拒否・往復・3マップ/4画面サイズ・ゴースト分離・3D縮小図・次会議のリセットを確認。
- `npm run build` 成功。

画面検証はChromiumのタッチ入力エミュレーション。iPhone/iPad実機や複数端末のオンライン対戦は未確認。本番の部屋・アカウントは変更していない。
